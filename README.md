# Surveillance AI Platform

A comprehensive video surveillance system with AI-powered object detection using CLIP (ViT-B/32) and real-time analysis capabilities.

## 🏗️ Repository Layout

```
Surveillance-AI/
├── frontend/          # React + Vite frontend application
├── backend/        # FastAPI backend with CLIP integration
├── docs/              # Project documentation and status reports
├── config/            # Configuration files
└── README.md          # This file
```

## 🚀 Quickstart

### Prerequisites
- **Node.js 18+** for frontend development
- **Python 3.10+** for backend services
- **FFmpeg** installed and available in system PATH

### Backend Setup
```bash
cd backend
pip install -r requirements.txt
uvicorn app:app --host 127.0.0.1 --port 8000 --reload
```

### Frontend Setup
```bash
cd frontend
copy .env.example .env   # Windows
# or cp .env.example .env   # Unix/Linux
npm ci
npm run dev
```

## 🎬 Video Previews

The system generates browser-compatible video previews:
- **Primary format:** H.264 MP4 (baseline profile, yuv420p)
- **Fallback format:** VP9 WebM for broader compatibility
- **Served via:** `/results` static file endpoint
- **Generated by:** FFmpeg CLI (system installation required)

## 🎭 Preview Modes

The system supports three preview modes for different use cases:

### Virtual Preview (Default)
- **Mode:** Timestamps only, no server-generated files
- **Behavior:** Frontend seeks and pauses directly from original media
- **Performance:** Instant loading, no server processing
- **Use Case:** Fast browsing and analysis of detection segments
- **Configuration:** `preview_generation.enabled: false` (default)

### Export Mode (On Demand)
- **Mode:** Server-generated MP4 clips with FFmpeg
- **Features:** Watermarking, SHA-256 hashing, browser-safe encoding
- **Trigger:** User clicks "Export" button on virtual previews
- **Output:** Downloadable MP4 files with metadata
- **Use Case:** Sharing, archiving, or detailed analysis of specific segments
- **Configuration:** `export.enabled: true` (default)

### Legacy Server Previews (Fallback)
- **Mode:** Server generates preview files during analysis
- **Behavior:** Traditional approach with pre-generated clip files
- **Performance:** Slower analysis, requires server storage
- **Use Case:** Backward compatibility or when virtual previews aren't suitable
- **Configuration:** `preview_generation.enabled: true` (fallback mode)

## 📥 URL Ingestion & Retention Policy

The system supports YouTube URL ingestion for analysis with automatic cleanup to prevent storage bloat. **URL-ingested videos are temporary by design** - they are downloaded to `uploads/url_tmp/` with a configurable retention period (default: 24 hours). The cleanup routine runs every 5 minutes and removes both temporary video files and provenance records older than the configured `keep_hours` setting. This ensures compliance with content rights while providing analysis capabilities for publicly available content. All URL ingestion requires explicit rights confirmation and is disabled by default (`url_ingest.enabled: false`) for legal safety.

## 🎬 Analyze from URL (YouTube)

The platform supports analyzing YouTube videos directly from URLs without requiring local file uploads. This feature enables analysis of publicly available content while maintaining legal compliance and storage efficiency.

### Feature Configuration

**Enable URL Ingestion:**
```yaml
# backend/config/clip_config.yaml
url_ingest:
  enabled: true                    # Enable YouTube URL ingestion
  provider: "youtube"              # Currently supports YouTube only
  max_duration_minutes: 120        # Maximum video duration (2 hours)
  max_size_mb: 2048               # Maximum file size (2GB)
  work_dir: "uploads/url_tmp"     # Temporary storage directory
  user_agent: "Mozilla/5.0"       # User agent for yt-dlp requests
  keep_hours: 24                  # Retention period for temp files
  preferred_quality: "bestvideo[ext=mp4]+bestaudio[ext=m4a]/mp4"
```

### Rights & Legal Compliance

**⚠️ Important Legal Notice:**
- **Rights Confirmation Required**: Users must explicitly confirm they have rights to download and analyze the content
- **Public Content Only**: Private, age-restricted, or DRM-protected videos cannot be processed
- **Temporary Storage**: Downloaded videos are automatically deleted after the retention period
- **No Permanent Storage**: Content is not permanently stored on the system
- **Feature Disabled by Default**: URL ingestion is disabled by default for legal safety

### Windowed Ingestion with yt-dlp

The system uses `yt-dlp` for efficient, windowed video downloads:

- **Time Window Selection**: Users can specify start and end times (e.g., `00:01:00` to `00:03:00`)
- **Efficient Download**: Only the requested time segment is downloaded, not the entire video
- **Quality Options**: Auto, 720p, 480p, 360p quality selection
- **Format Optimization**: Prefers MP4 with H.264 + AAC for compatibility

**Example yt-dlp Command:**
```bash
yt-dlp --download-sections "*60-180" -f "best[height<=720][ext=mp4]" -o "uploads/url_tmp/yt_videoId_timestamp.mp4" "https://www.youtube.com/watch?v=..."
```

### Virtual Previews + Export-on-Demand

URL-ingested videos integrate seamlessly with the existing preview system:

- **Virtual Previews**: Frontend seeks and pauses directly from the downloaded video file
- **Export-on-Demand**: Users can export specific segments as downloadable MP4 clips
- **Watermarking**: Exported clips include timestamps and analysis metadata
- **SHA-256 Hashing**: Exported files include integrity verification

### Retention & Cleanup Behavior

**Automatic Cleanup System:**
- **Frequency**: Runs every 5 minutes
- **Retention Period**: Configurable via `keep_hours` (default: 24 hours)
- **Cleanup Scope**: Removes both temporary video files and provenance records
- **Storage Management**: Prevents storage bloat from accumulated temp files

**Cleanup Process:**
1. Identifies files older than `keep_hours`
2. Deletes temporary video files from `uploads/url_tmp/`
3. Removes corresponding provenance records from database
4. Logs cleanup activities for monitoring

### Limits & Error Handling

**Size & Duration Limits:**
- **Max Duration**: 120 minutes (configurable)
- **Max Size**: 2048 MB (configurable)
- **Graceful Rejection**: Returns HTTP 413 with descriptive error messages
- **Automatic Cleanup**: Downloaded files are removed when limits are exceeded

**Common Error Scenarios:**
- **Private Videos**: "This video is private. Please use a public video."
- **Age-Restricted**: "This video is age-restricted and cannot be downloaded."
- **DRM Protection**: "This video has DRM protection and cannot be downloaded."
- **Geographic Restrictions**: "This video is not available in your region."
- **Size/Duration Limits**: "Video size/duration exceeds configured limits."

### Provenance Tracking

All URL-ingested content is tracked with comprehensive metadata:

- **Source URL**: Original YouTube URL
- **Video Metadata**: Title, channel, duration, quality
- **Time Windows**: Start/end times of downloaded segments
- **Analysis Status**: Tracks whether analysis has been completed
- **Creation Timestamp**: UTC timestamp for cleanup scheduling
